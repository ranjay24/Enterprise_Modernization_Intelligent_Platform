{{definition}}

{{service_plan_json}}

{{source_boundary_json}}

{{analysis_context_json}}

{{file_path}}

{{file_description}}

{{shared_types_json}}

{{regeneration_context_json}}

## Deliverable
Return ONLY valid JSON with exactly two keys:
- "path": "{{file_path}}" (must match the FILE TO GENERATE exactly)
- "content": "<the complete file content>"

Do NOT wrap the JSON in markdown fences. Do NOT emit anything before or after the JSON.

## Rules
1. The path in the response MUST equal {{file_path}}.
2. Use the service package, class names and tables from the plan only.
3. Use ONLY the class names, interfaces and packages listed in SHARED TYPES.
   Never invent, rename, or repackage a type. The file's own class name MUST be
   the name SHARED TYPES assigns to this path.
4. Use correct Spring annotations (@RestController, @Service, @Repository, @Entity,
   @Table, @FeignClient, @KafkaListener, @RabbitListener) and Resilience4j
   annotations matching the plan.
5. The service owns its database tables; never import another service's entities.
6. Reference only dependencies listed in the pom.xml for this service.
7. When regeneration_context has findings, fix them.
8. Code must compile: imports must match the SHARED TYPES packages exactly, and
   every cross-file reference (imports, extends, implements, generic parameters,
   method calls) must use a SHARED TYPES name.
9. If the requested file is a config resource (pom.xml, yml, Dockerfile,
   openapi.yaml), emit the complete, valid content.
